# Agent guide — jingerchong.com

This is the single repository guide for any coding agent. Read it with `README.md`,
`_config.yml`, and `TODO.md` before changing the site. It describes the current
codebase; inspect the actual templates and content before assuming an older plan
has been implemented.

## Purpose and editorial direction

- This is Jinger Chong's personal robotics research portfolio and a resource for
  summer research internship applications. Present research, publications,
  industry R&D, and selected robotics projects clearly and accurately.
- Preserve the site's recognizable identity: navy `#08415C`, yellow `#EFCA08`,
  robot-arm logo and favicon, navy header/footer, yellow selection, uppercase
  letter-spaced headings, and the navy `h2` underline. The tokens live in
  `_sass/_tokens.scss`; `assets/main.scss` imports the other Sass partials.
- Keep Jekyll and GitHub Pages compatibility. This site uses Minima with Sass,
  Liquid, Markdown, and a small amount of vanilla JavaScript. Avoid adding a
  frontend framework or build tool for ordinary site changes.
- Preserve existing material and URLs when reorganizing content. Historic posts
  have root-level URLs; new project pages use `/projects/:slug/`. Check both
  before changing a slug or link. Legacy redirects and CI remain tasks in
  `TODO.md`; do not assume they already exist.

## Stack and local verification

- `Gemfile`/`Gemfile.lock` pin GitHub Pages `~> 232.0`, Jekyll 3.10, Minima
  `~> 2.5`, and `jekyll-feed`, `jekyll-sitemap`, `jekyll-seo-tag`.
- Use Ruby 3.3 with the Windows development tools; Ruby 4 is incompatible with
  this locked dependency set. `README.md` has verified PowerShell setup and
  local build/serve commands. On this machine, the working commands include:

  ```powershell
  $env:Path = 'C:\Ruby33-x64\bin;' + $env:Path
  bundle install
  bundle exec -- C:\Ruby33-x64\bin\jekyll.bat build
  bundle exec -- C:\Ruby33-x64\bin\jekyll.bat serve
  ```

- Jekyll does not reload `_config.yml` while serving; restart after edits.
  `_site/` is generated and ignored. Do not edit or commit generated output.
- `CNAME` and `_config.yml` target `jingerchong.com`. `site.email` is the MIT
  address; `_config.yml` also defines the public CV URL.

its front matter also records `/experience/` as an old URL. Verify whether a
redirect is actually generated before relying on it.

## Content conventions

### Projects and historical posts

- `_projects/*.markdown` uses front matter such as `title`, `slug`, `order`,
  `tier` (`featured`, `normal`, or `archive`), `stack`, `blurb`, `summary`, `cover`,
  `problem`, `approach`, `results`, and optional `todo`. The detail layout is
  `_layouts/project.html`; cards are in `_includes/`. Archive entries with
  `in_service: true` appear through About → Service instead of the Archive list.
- `_posts/` front matter uses `area` to place a post on an archive category
  page. The intended area names and display order are `categories_order` in
  `_config.yml`: Research, Perception & Autonomy, Systems & Hardware, Teaching,
  Archive. Some older posts may still use `category`/`categories`; normalize
  these when editing the relevant post, since `_layouts/category.html` filters
  by `area` only.
- `_archives/*.markdown` provides category pages with explicit `title` values.
  Do not derive category titles from slugs: ampersands and multiword names do
  not round-trip. Keep old root post URLs working when moving content.
- Old post covers conventionally live at `assets/images/<post-slug>/cover.webp`.
  `_layouts/post.html` checks that a cover exists before rendering it. Gallery
  documents in `_grids/<post-slug>/grid-N.markdown` match posts using a **path
  substring** and then collect static images from the matching directory.
  Keep post slugs distinct without substring overlaps; zero-pad gallery image
  names if their order matters. Avoid broken or unconditional media references.

### Research, experience, publications, and About

- `_research/` front matter includes `title`, `order`, `status`, `venue`,
  `blurb`, `metrics`, `tags`, and optional `todo`. It is draft content until a
  page template explicitly renders it. `_records/` has legacy research and
  experience summaries (`type`, `order`, `show`, optional `page`); do not assume
  changing a record updates a public page.
- `_experience/` entries use `org`, `role`, `start`, `end`, `location`,
  `headline`, `bullets`, `featured`, `confidential`, and optional `todo`.
  `_layouts/experience.html` filters displayed organizations by name. Inspect
  that filter before adding an entry or changing an organization string.
- `_data/publications.yml` contains publication and patent metadata and
  links. `_data/education.yml`, `_data/skills.yml`, and `_data/service.yml`
  are the live About sources; `_data/links.yml` is the live social link source.
  Do not update the unused duplicates and expect the page to change.
- `/todo/` is a noindex dashboard, but `_layouts/todo.html` currently scans
  TODO arrays only in `_research`, `_experience`, `_projects`, publications,
  and `site.pages`. It does not scan every file, `_records`, or legacy posts.
  `_includes/todo.html` hides inline TODO badges in production. `TODO.md` is
  the human-maintained launch checklist and may contain additional work.

## Factual accuracy, confidentiality, and accessibility

- Use current owner-provided material and verified public sources for factual
  claims. Do not infer dates, degrees, metrics, authors, awards, publication
  status, patent numbers, media, or URLs from old planning notes. Preserve
  existing content unless the owner asks to remove it; record unresolved
  changes in `TODO.md` or a front-matter `todo` entry.
- `TODO.md` identifies facts that still require owner review, especially GE
  Vernova public wording/metrics, Rotor LiDAR compression ratio, and ICRA
  2027 anonymity/preprint policy. A `confidential: true` flag in content is
  **not** a blanket renderer-level privacy guarantee. Check every rendered
  field, media path, link, and generated page before publishing sensitive work.
- Keep original résumé documents and personal contact details out of the
  published site. `downloads/jinger-chong-cv.pdf` is the intended public copy;
  check redaction before replacing it. Do not expose phone numbers, street
  addresses, proprietary internship details, or unpublished patent material.
- For unknown media, use the committed `assets/placeholder.svg` only with a
  specific TODO describing the needed asset and target path. Do not invent or
  hotlink imagery. For unknown URLs, prefer no link plus a TODO over a dead
  `href="#"`.
- Maintain semantic headings/landmarks, meaningful image alt text, visible
  keyboard focus, readable contrast, responsive layouts, and reduced-motion
  behavior for any autoplay media.

## Change workflow

1. Inspect `git status` and preserve unrelated user changes. Read the actual
   source and templates for the affected route; older briefs and comments can
   be stale. Make small, focused text edits, preferably with `apply_patch`.
2. If content changes, check both the public view and the relevant TODO source.
   If a new page is public, verify its URL, navigation, metadata, links, media,
   and confidentiality. Do not silently drop earlier projects or information.
3. Build with the locked Ruby/Bundler setup, then check affected generated
   routes and references. For broad changes, smoke-check `/`, `/research/`,
   `/industry/`, `/projects/`, `/projects/archive/`, `/about/`, `/todo/`,
   category pages, and representative root post and project detail pages.
   Check for missing local assets, empty links, leaked placeholders or private
   files, and run `git diff --check`.
